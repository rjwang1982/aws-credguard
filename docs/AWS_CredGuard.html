AWS CredGuard：本机不存明文 AKSK，
每次启用凭证都要本人按指纹

一台 Mac 上管着几十个 AWS 账号的长期密钥，人和 AI 智能体（Kiro、Quick、MCP）共用。本方案把 AKSK 交给 Mac 的安全芯片（Secure Enclave）加密，解密必须按 Touch ID；交给工具的只有 1 小时有效的 STS 临时凭证；原来的 --profile 用法不变。

默认做法下，读一个文件就能拿走全部账号

AWS CLI 默认把长期 AKSK 明文写在 ~/.aws/credentials；账号越多、智能体越多，暴露面越大。

风险改造前改造后
明文存储credentials 里存着全部 AKSK没有明文，只有 Secure Enclave 加密的密文
恶意 npm/pip 包、浏览器插件读一个文件就能拿走全部密钥只能拿到密文，私钥在芯片里导不出来
云盘同步、Time Machine明文被同步和备份带走带走的是密文，离开本机芯片无法解密
智能体静默使用随时可用，本人不知情每个 profile 每小时首次使用时弹 Touch ID
长期密钥外泄工具直接拿到长期 AK工具只拿到 1 小时有效的临时凭证

架构：在 AWS CLI 和密钥之间加一道指纹关口

琥珀色是凭证经过的路径。调用方只看到 config 里的 credential_process，不知道密钥存在哪里。

一次调用的时序：每个 profile 每小时只按一次指纹

以 Kiro 调用 aws sts get-caller-identity --profile dev 为例。缓存命中时跳过 ③–⑤，不会弹任何窗口。

日常只需记住 8 个命令

管理函数在 ~/.aws/aws_profile_manager.sh，由 ~/.zshrc 自动加载。

命令作用
aws-ls列出 profile，🔐 表示已加密
aws-add <名> <AK> [region]SK 交互输入；先验证 STS，再加密、写 config
aws-rm <名>输入 y 确认；删除密文、缓存和 config
aws-show <名>查看配置和缓存到期时间，不显示密钥
aws-region <名> <region>修改 region，并作废旧缓存
aws-test [名|--all]验证身份
aws-use <名> [命令]用该 profile 执行一条命令，或设为当前 shell 默认
aws-lock清空缓存，下次重新按指纹
 
# 原有用法不变，首次弹 Touch ID
aws sts get-caller-identity --profile dev

# 新增客户账号
aws-add newclient AKIA... cn-northwest-1
Secret Access Key: ********
# ✅ 已添加，身份 arn:aws-cn:iam::…
# 记得同步存入 SafeInCloud

# 离开电脑前
aws-lock
不要在 ~/.zshrc 里设置全局 AWS_REGION。它会覆盖 profile 自己的 region，导致中国区账号访问海外 STS 地址，报 InvalidClientTokenId。

防得住文件被读走，防不住授权后 1 小时内的滥用

加密只解决"密钥怎么存"，权限要靠 IAM 最小权限来收紧。

防得住

  • 恶意包、插件扫描 ~/.aws
  • 云盘同步、备份、磁盘被拷走
  • 智能体在你不知情时启用新的 profile
  • 工具在日志或报错里打印出长期 AK
  • 篡改缓存文件来跳过指纹（缓存只存临时凭证，不再有"已验证"标记文件）

防不住

  • 按过指纹后 1 小时内，以你身份运行的进程能读取缓存的临时凭证
  • 智能体被提示词注入后，在已授权窗口内滥用权限
  • 本人在不清楚原因时按了指纹
  • root 密钥换不了 STS 临时凭证，只能直接输出长期密钥

配套治理：加密只管"怎么存"，权限要靠 IAM 收紧

用 scripts/audit_permissions.sh（只读）盘点后，按下表处理。

发现处理优先级
Root 账号的 Access Key查最近使用时间后删除，root 只用于控制台并开 MFA高
AdministratorAccess 给了智能体使用的 profile为智能体单独建只读用户（如 agent-readonly），管理员 profile 只留给本人高
名义只读但带 IAMFullAccess去掉 IAMFullAccess，防止自我提权中
同一 IAM 用户配置了多个 profile 名合并为一个，其余改别名中
密钥超过 90 天未轮换轮换后 aws-add 重新加密，并同步离线备份中

故障与恢复

现象处理
custom-process 报错aws-lock 后重试；或执行 bash -x ~/.aws/bin/aws-cred <名>
InvalidClientTokenId检查 env | grep AWS_REGION；用 aws-test 验证
增删指纹后全部失败芯片密钥已失效：重装后用 SafeInCloud 恢复
换了新 Mac芯片密钥不能迁移：同上，在新机器上重建
智能体卡住屏幕已锁定或指纹窗口没人处理：解锁屏幕或按指纹
 
# 安装 / 重建
git clone https://github.com/rjwang1982/aws-credguard.git && cd aws-credguard
./install.sh
source ~/.zshrc
aws-add <名> <AK> <region>   # 从 SafeInCloud 逐个恢复

# 验收
grep -rlE 'AKIA[0-9A-Z]{16}' ~/.aws | grep -v /vault/ \
  || echo "无明文"
ls ~/.aws/credentials        # 应不存在
aws-test dev                  # 按指纹后返回 ARN
